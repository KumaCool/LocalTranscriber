# 阶段 E：真实转写进度与动态 ETA 验收

## 验收范围

阶段 E 为单文件转写增加持久化、跨进程可查询的阶段、实际工作量、单调百分比和动态 ETA 范围，并更新 Hermes 调用规范。状态查询不启动模型、不取得 worker 锁、不监听端口，默认不返回输入路径或正文。

## 实现语义

- 阶段权重：媒体探测与标准化 `0%–5%`，模型加载和 VAD `5%–15%`，核心 ASR/说话人处理 `15%–95%`，结果整理和导出 `95%–100%`。
- FunASR 1.3.30 的原生文件级回调在真实运行中只产生 `(1, 1)`，不能直接代表核心推理完成。
- engine 适配层因此从 VAD 结果建立总语音时长，并按实际进入 ASR 的音频批次累计处理毫秒；speaker 子模型不重复计入核心工作量。
- 百分比单调，失败和取消保留最后可信进度；只有所有导出成功写出后才迁移为 `succeeded/100%`。
- ETA 使用单调时钟和近期批次速度，输出上下界；样本不足时为 `calculating`，停滞时扩大区间并标记 `low`。
- CLI 命令 `local-transcriber job status <id> --runtime-dir ... --json` 只读输出脱敏状态。

## 真实长音频校准

授权样本为约 27 分钟中文音频，媒体时长 `1619.264` 秒。三次正式校准均固定：

- `--language zh`
- `--threads 2`
- 单 worker
- 已缓存的 SenseVoiceSmall、FSMN-VAD 与 CAM++
- FunASR `1.3.30`

| 运行 | 墙钟耗时 | 核心工作量 | 终态 | 产物回读 |
|---|---:|---:|---|---|
| 1 | 265.145 秒 | 807610 / 807610 ms | `succeeded` | JSON 可解析，MD/TXT/SRT/media 非空 |
| 2 | 260.364 秒 | 807610 / 807610 ms | `succeeded` | JSON 可解析，MD/TXT/SRT/media 非空 |
| 3 | 251.684 秒 | 807610 / 807610 ms | `succeeded` | JSON 可解析，MD/TXT/SRT/media 非空 |

三次核心总量完全一致，证明当前适配层没有把 FunASR 的文件级 `(1,1)` 或 speaker 子调用误当作全局完成量。运行中已跨进程读到可解析状态，例如核心阶段 `276820 / 807610 ms`、`42.42%`、ETA `148–232` 秒；该区间覆盖该检查点的实际剩余时间。

本轮只保存项目忽略目录中的运行证据，不提交私人录音、转写正文、绝对输入路径或机器身份信息。同一音频重复三次只证明该场景下的稳定性，不代表噪声、重叠、长静音或负载突变场景均达到同等 ETA 精度。

## Hermes 验收

项目 Skill 已明确：

- 启动后记录 CLI 立即输出的任务 ID；
- 仅在用户询问时查询，除非用户明确要求定时通知；
- 禁止紧密轮询；阶段未变化且进度变化不足 5 个百分点时去重；
- 终态通知一次，并继续校验 canonical JSON 与所有导出；
- 百分比和 ETA 必须描述为工程估算。

真实运行期间状态命令成功跨进程读取运行中任务，且没有启动第二个 worker、创建 HTTP 服务或暴露监听端口。

## 自动化门禁

- 全量测试：55 项通过（完成文档前最终复跑）
- Ruff lint：通过
- Ruff format check：通过
- `git diff --check`：通过
- Markdown 相对链接：通过

## 结论与边界

阶段 E 验收通过。当前实现提供真实事件驱动的工程进度和动态 ETA 范围，而不是按已运行时间制造的匀速假进度。ETA 仍是估算；不同音频条件和主机负载可能扩大误差，低置信度必须如实展示。阶段 F 的批量队列、显式后台管理器和崩溃恢复不属于本阶段。
